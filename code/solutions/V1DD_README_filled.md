## Overview

### Description
The **V1 Deep Dive (V1DD)** dataset characterizes the relationship between neural function and connectivity in mouse primary visual cortex (V1). Visual responses from pan-excitatory neurons were recorded with two-photon calcium imaging across an ~800 × 800 µm region of V1, spanning all cortical layers from pia to white matter. Because the same tissue is also being reconstructed with electron microscopy, the dataset is designed to support study of the **functional connectome** — linking each neuron's activity to its anatomy and wiring.

It is useful for questions about single-cell and population activity in V1: orientation/direction tuning, spatial receptive fields, responses to natural stimuli, and (in combination with the EM reconstruction) structure–function relationships.

### At a glance
- **4 mice** total.
- **~50,000 neurons per mouse.**
- Imaging planes per mouse: **150 two-photon** planes (plus 7 three-photon planes; **only the 2P data is shared here**).
- Planes are spaced ~16 µm apart.
- Imaging is organized as **5 lateral columns**, each imaged in **5 vertically stacked volumes**, with **6 planes per volume** (`plane-0` … `plane-5`).
- Only ROIs passing the soma filter are included (see Responses → QC below).

The metadata file, `data/metadata/V1DD_metadata.csv`, provides curated session-level data for filtering. It was generated by querying the metadata database and scraping "up-leveled" fields into a flat CSV; the code that produces it lives in `/code/metadata`, and can be re-run if additional fields are needed. The database is also browsable through the metadata portal (see the temporary data-portal links in the tutorial). Each row is one session and each column is a metadata field. Relevant columns include:

- `subject_id`: mouse identifier
- `session_start_time`, `session_end_time`: session timing (useful as a sanity check on trace duration)
- `modality`: recording modality collected in the session
- `genotype`: transgenic line(s) — see the [transgenic tools page](https://allenswdb.github.io/background/transgenic-tools.html)
- `column`, `volume`: the lateral column and vertical volume imaged (5 columns × 5 volumes; each volume = 6 planes)

### NWB file structure

Each session's `.nwb.zarr` is a hierarchical (HDF/Zarr) container. The pieces used in the tutorial:

```
<SUBJECT_ID>_<ACQUISITION_DATE_TIME>.nwb.zarr/
├── processing/
│   ├── plane-0 … plane-5/          # one entry per imaging plane (6 per volume)
│   │   ├── dff                     # ΔF/F traces (frames × ROIs) + timestamps; .rois metadata table
│   │   ├── demixed                 # fluorescence after demixing overlapping ROIs
│   │   ├── events                  # inferred spike events (deconvolved from ΔF/F)
│   │   ├── neuropil_corrected      # fluorescence after neuropil subtraction
│   │   ├── neuropil_fluorescence   # raw surrounding-neuropil signal
│   │   ├── raw                     # raw ROI fluorescence, before correction
│   │   ├── image_segmentation      # ROI spatial masks
│   │   └── images                  # FOV reference images (e.g. max projection)
│   └── behavior/
│       ├── running_speed           # array + timestamps (cm/s)
│       └── eye_tracking            # table incl. pupil_area, timestamps
├── intervals/
│   ├── epochs                      # coarse blocks: which stimulus type ran when
│   └── stimulus_table              # trial-by-trial stimulus presentations
└── stimulus/                       # actual stimulus images / movie frames
```

> Access pattern: use a mix of dot (`.`) and bracket (`[]`) notation, e.g. `nwb.processing['plane-3']['dff']`. Container locations can vary across datasets, so scan all containers first.

## Dataset features

### Neurophysiological data (`processing/plane-{0..5}/`)
#### Modality
- **Two-photon calcium imaging** of pan-excitatory neurons in V1 (3-photon planes exist but are not shared here).
- Multiple activity representations are stored per plane; **`dff` (ΔF/F) is the recommended starting point** for analysis. `events` gives sparser, deconvolved spike-like events; `raw`, `neuropil_fluorescence`, `neuropil_corrected`, and `demixed` capture earlier processing stages.
- `dff.data` is shaped **(frames × ROIs)**; `dff.timestamps` gives the acquisition time (s) of each frame. Derive the imaging rate from the timestamps (`1 / np.median(np.diff(ts))`) — it is per-plane, not a single dataset-wide number.

#### Anatomy
- Region: **primary visual cortex (V1)**, an ~800 × 800 µm field spanning all layers (pia → white matter).
- Depth is organized by **volume** and **plane** (6 planes per volume, ~16 µm spacing); the `column`/`volume` metadata locates each acquisition laterally and in depth.

#### Cell types
- **Pan-excitatory** neurons (accessed via transgenic line — confirm the specific genotype(s) from `metadata.genotype` and the [transgenic tools page](https://allenswdb.github.io/background/transgenic-tools.html)).

#### Responses
- ROIs (segmented somata) are described in the per-plane **ROI table** (`dff.rois.to_dataframe()`), one row per ROI. Rows align with **columns of `dff`** (row *i* ↔ column *i*).
- Key ROI-table columns:
  - `id` — links the ROI table to `dff` (row ↔ column)
  - `roi` — links ROIs to the **EM/connectomics** data (used on the connectomics day)
  - `is_soma` — QC flag
  - `pixel_mask` — spatial footprint of the ROI (sparse: list of (x, y, weight) per pixel)
  - `pika_roi_id`, `pika_roi_confidence` — segmentation-pipeline identifiers/confidence ("pika" = internal pipeline name); raw ids carry no analysis meaning
- Population size: **~50,000 neurons per mouse** (across all planes); per-plane/session counts come from the ROI table (`roi_table.shape`).
- **QC:** the ROI table is **filtered to somata** (`is_soma`), so ROI indices are **not continuous**. Check `roi_table.is_soma.value_counts()`. No further QC is applied by default; decide per-analysis whether additional filtering is needed.

### Stimulus table (`intervals/stimulus_table/`)
The mouse passively viewed a battery of **parametric** and **naturalistic** visual stimuli. Timing is stored in `intervals`: **`epochs`** marks coarse blocks (which stimulus type ran when), while **`stimulus_table`** has trial-by-trial detail (one row per presentation, with start/stop time and feature columns). The actual images/frames live in the **`stimulus`** container. Each unique stimulus condition has a `stimulus_condition_id`; repeated presentations share the id, so it's the key for grouping repeats (e.g. trial averaging) and matching conditions across sessions.

Stimuli present, what they probe, and their feature columns:
- **drifting_gratings_full** — full-field moving sinusoidal grating; probes orientation/direction selectivity and temporal-frequency preference. Features: `temporal_frequency`, `spatial_frequency`, `direction`.
- **drifting_gratings_windowed** — same, but shown in a local patch; probes *where* in visual space a neuron responds. Features: as above plus `center_azimuth`, `center_elevation`.
- **locally_sparse_noise** — grid of random bright/dark squares; maps spatial receptive fields. Feature: `frame`.
- **natural_images** — repeated natural photographs; complex naturalistic spatial structure. Features: `image_order`, `image_index`.
- **natural_movie** — repeated natural movie clip; naturalistic spatiotemporal structure. Feature: `frame`.
- **spontaneous** — gray screen; baseline. No features.
- For `natural_images`, `natural_movie`, `locally_sparse_noise`, the index columns point into the images/frames stored in the `stimulus` container. See the [stimulus reference](https://allenswdb.github.io/physiology/ophys/V1DD/V1DD-stimuli.html).

### Behavioral data (`processing/behavior/`)
- **Running speed** — `running_speed` array (cm/s) with its own `timestamps`.
- **Eye tracking** — table including `pupil_area` (pixels²) and `timestamps`; has many additional columns.
- **Alignment caveat:** neural, running, and eye-tracking streams have **different lengths and different sampling rates**, so they must be aligned via their **timestamps**, not by sample index. This is the central multi-stream lesson of the tutorial.
- **QC:** eye-tracking data typically contains **NaNs** (blinks/lost tracking); use NaN-aware operations (e.g. `np.nanmean`) when averaging pupil data. _Confirm whether running speed needs any additional filtering._

#### History
- Passive viewing; no operant behavioral task or pre-training curriculum is central to this dataset. _If any habituation/training details are relevant, add them here._

### Manipulations
- None in the shared 2P data (passive viewing). The linked **EM reconstruction** of the same tissue is the paired structural modality rather than an in-vivo manipulation.

## Opportunities + Limitations
**Opportunities**
- Dense, layer-spanning V1 population imaging (~50k neurons/mouse) for single-cell and population analyses.
- Paired EM reconstruction enables **structure–function** work (via the `roi` identifier).
- Rich stimulus battery supports tuning, receptive-field, and natural-stimulus analyses in the same neurons.

**Limitations**
- **Calcium imaging**, not spikes: ΔF/F is a slow, indirect proxy for firing; `events` is inferred, not ground-truth.
- ROI table is **soma-filtered** (non-continuous indices); non-soma signals are excluded.
- Streams are **not pre-aligned**; timestamp alignment is required, and eye-tracking has missing samples.
- Only **2P** planes are shared here (not the 3P planes).
- _Note any session-to-session variability or missing fields you encounter._
